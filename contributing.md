# Contribution Guidelines

Please note that this project is released with a
[Contributor Code of Conduct](code-of-conduct.md). By participating in this
project you agree to abide by its terms.

---

Thank you for contributing to Awesome BLIT386! Before opening a pull request,
make sure your suggestion meets the following guidelines.

## What belongs here

- The resource is related to [BLIT386](https://github.com/blit386/blit386), the
  palette-first WebGPU retro engine.
- The resource is genuinely useful: a library, tool, tutorial, article, demo,
  game, template, or community resource that other people would want to find.
- The resource is actively maintained and works as described, or is a finished
  piece (such as an article or video) that remains accurate.

## Pull request guidelines

- Add one resource per pull request so each can be discussed on its own.
- Place the entry in the most fitting section, keeping each section in
  alphabetical order.
- Use the format `[Name](link) - Description.` with a single space before and
  after the minus.
- Start the description with an uppercase letter and end it with a period.
- Keep the description short and factual; no marketing language or emoji.
- Check that the link works and points directly to the resource.
- Search the list first to avoid adding a duplicate link.
- Update the Table of Contents if you add a new section.

## Updating your PR

A lot of times, making a PR adhere to the standards above can be difficult.
If the maintainers notice anything that we would like changed, we will ask you
to edit your PR before we merge it. There is no need to open a new PR, just edit
the existing one. If you are not sure how to do that,
[here is a guide](https://github.com/RichardLitt/knowledge/blob/master/github/amending-a-commit-guide.md)
on the different ways you can update your PR so that we can merge it.
